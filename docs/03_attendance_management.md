
# 要件定義書：03_勤怠管理モジュール (03_attendance_management.md)
 
## 1. 目的・概要
 
本モジュールは、**02_打刻管理モジュール**の打刻ログから算出した実労働時間に対し、勤怠フラグ・残業・深夜割増・事業別時間内訳・給与スナップショットを紐づけて管理・集計する機能である。
 
**事業別時間管理が必要な理由（業務背景）：**
当社では複数の委託事業（例：本社業務・就職氷河期支援事業・障がい者雇用支援事業など）を並行して運営している。給与は一旦本社から全額支払われるが、各事業の人件費は「当該事業に従事した時間」に応じて委託元へ事業終了前に請求する仕組みとなっている。そのため、**1日の中で「何時から何時まで何の事業に従事したか」を時間帯単位で正確に記録・可視化し、事業ごとの人件費を正確に算出・請求できる状態を維持すること**が本モジュールの最重要要件である。
 
本モジュールは以下のマスターデータの定義・管理拠点でもある。
- **手当マスタ**（`wp_allowance_masters`）: 01_ユーザー管理モジュールの個人手当設定が参照する
- **事業マスタ**（`wp_businesses`）: 03・04・05すべてのモジュールが事業IDと色情報を参照する
月次の勤務実績を 3 段階のワークフローで確定し、承認完了時に給与条件をスナップショットとして固め、**弥生給与計算**へのCSV連携および監査対応 PDF 出力を提供する。
 
**プラグイン構成（PHP実装の前提）：**
 
本モジュール（03_勤怠管理）と **04_交通費・車両借上げモジュールは、同一の WordPress プラグイン内の別モジュール**として実装する。両者は提出フロー・スタッフ画面（タブ統合）・管理者画面（タブ統合）・設定画面（交通費設定）を密に共有するため、プラグインを分割せず1つのプラグイン内に同居させる。
 
- 共有するもの：月次ワークフロー（`wp_monthly_summary`）、事業マスタ（`wp_businesses`）、提出・ロックの状態、スタッフ／管理者のタブUI。
- モジュール分割の単位：機能ディレクトリ（例：`includes/attendance/`・`includes/travel/`）で論理的に分けるが、プラグイン本体・DBテーブルの所有・有効化フックは共通とする。
- これにより、03の提出操作で04のデータも同一トランザクション・同一フック内でロックでき、モジュール間連携をプラグイン境界をまたがずに実現する。

## 2. マスター設定要件（管理画面）
 
### 2.1. 給与計算サイクル設定
 
`システム管理者（administrator）` のみが変更できるプラグイン設定（`設定 > 給与計算サイクル`）に以下の項目を設ける。
 
| 設定項目 | 選択肢 | デフォルト |
|---|---|---|
| 締め日 | 当月20日 / 当月25日 / 当月末日 / 翌月20日 / 翌月25日 | 当月末日 |
| 支払日 | 当月10日 / 当月20日 / 当月25日 / 翌月10日 / 翌月20日 / 翌月25日 | 翌月25日 |
 
- 締め日設定に基づき、各月度のタイムカード画面の対象日付範囲を自動生成する。
  - 例：末日締め → 対象期間 = `YYYY-MM-01` 〜 `YYYY-MM-末日`
  - 例：20日締め → 対象期間 = `前月21日` 〜 `当月20日`
- **締め日変更の制限：** `確定` ステータスの月度が存在する場合、締め日の変更操作をブロックし警告を表示する。変更する場合は管理者が全確定データのロック解除を明示的に承認してから行う。

### 2.2. 手当マスタ設定
 
メニュー階層：`社員管理 > 手当マスタ`
 
| フィールド | 型 | 説明 |
|---|---|---|
| `id` | INT AUTO_INCREMENT | 主キー |
| `allowance_code` | VARCHAR(20) | 手当コード（一意） |
| `allowance_name` | VARCHAR(100) | 手当名（例：役付き手当、皆勤手当） |
| `is_active` | TINYINT(1) | 有効フラグ |
| `sort_order` | INT | 表示順 |
 
**デフォルト登録手当：** 役付き手当 / 皆勤手当 / 家族手当 / 在宅ワーク手当 / 職務手当 / 家計補助手当
 
**手当の追加操作：** 管理者が新しい手当を追加すると、**01_ユーザー管理モジュール**の各社員の給与設定画面に金額入力欄（`wp_user_allowances` の新行）が自動的に追加される。
 
**手当の削除操作（論理削除）：**
- `is_active = 0`（無効化）として論理削除する。物理削除は不可。
- 無効化された手当は新規入力欄に表示されなくなるが、`wp_user_allowances` に既存の金額レコードは保持され、スナップショット時に参照される。
- **→ 01_ユーザー管理モジュールとの連携：** `wp_user_allowances` の `allowance_master_id` はこのテーブルの `id` を参照する。

## 3. 機能要件
 
### 3.0. データフロー全体像（打刻起点・PHP実装の指針）
 
本モジュールのすべての勤怠データは、**02_打刻管理モジュールの打刻ログ（`wp_attendance_logs`）を唯一の起点**とする。スタッフが時刻を直接入力するのではなく、打刻実績から実労働時間・休憩時間帯を導出し、それに事業を割り当てる流れである。PHP実装時は以下のデータフローを厳守する。
 
```
【1】打刻（02モジュール / wp_attendance_logs）
      clock_in / break_in / break_out / clock_out
                    │
                    ▼
【2】実労働時間・休憩時間帯の算出（03モジュール）
      総休憩時間   = Σ(break_out − break_in)
      実労働時間   = clock_out − clock_in − 総休憩時間
      休憩時間帯[] = 各 break_in〜break_out の区間（複数可）
      → wp_daily_attendance.actual_minutes に保存
                    │
                    ▼
【3】事業別割り当て（スタッフ入力 / wp_project_hours）
      実労働時間の「働いた時間帯」だけを事業に割り当てる。
      休憩時間帯は割り当て対象から除外（谷間として空ける）。
      Σ(事業割り当て分) = 実労働時間 でバリデーション。
                    │
                    ▼
【4】グリッド描画（タイムカード画面）
      ・事業割り当て（wp_project_hours）→ 事業カラーで塗り
      ・休憩時間帯（打刻由来）→ 塗らず「休憩」表現で空ける
      ・出退勤（打刻由来）→ サマリー行に表示
```
 
**重要な設計原則（PHP実装時の遵守事項）：**
 
1. **休憩時間帯は打刻データ由来であり、固定値ではない。** グリッド上の休憩の位置・長さは、当日の `break_in`〜`break_out` の打刻実績から動的に決まる。人によって・日によって休憩時刻が異なるため、UI・実装ともに休憩時刻をハードコードしてはならない。
2. **休憩時間帯は事業別割り当ての対象外。** 事業に割り当てるのは「実際に働いた時間帯」のみ。休憩の谷間は事業セルを描かず空白（休憩表現）とする。
3. **打刻の丸め：** グリッド描画・事業割り当ての時間境界は15分単位で扱う。出勤は切り上げ（roundUP）、退勤は切り下げ（roundDOWN）方向に丸め、塗り範囲を内側に寄せる（労働時間の過大計上を防ぐ）。実労働時間そのものの算出は打刻の実時刻で行い、丸めはグリッド表示・事業割り当ての時間境界にのみ適用する。

### 3.1. 実労働時間の算出ロジック
 
**02_打刻管理モジュール**の `wp_attendance_logs` を参照し、日次の実労働時間・残業時間を以下のルールで算出する。
 
#### 基本計算式
 
```
総休憩時間 = Σ（break_out の punched_at − 対応する break_in の punched_at）
実労働時間（分） = clock_out − clock_in − 総休憩時間
```
 
#### 残業・深夜時間の識別と計算
 
| 区分 | 計算ルール |
|---|---|
| 法定内残業 | `MAX(0, MIN(実労働時間, 480分) - 所定労働時間)` ※所定が8h未満の場合のみ発生 |
| 法定外残業（日次） | `MAX(0, 実労働時間 - 480分)` |
| 法定外残業（週次） | 週の実労働時間合計が 2400分（40h）を超えた分（日次法定外として計上済みの分を除く） |
| 深夜労働 | 22:00〜翌5:00 に打刻ログが重なる時間帯の実働分 |
 
> **深夜×法定外の重複処理：** 深夜時間帯に行われた法定外残業は、`overtime_illegal` と `late_night_hours` の両方に計上する（弥生給与計算の入力仕様に合わせ、それぞれ独立した時間として保持する）。
 
**所定労働時間の参照元：** `wp_usermeta` の `scheduled_work_hours`（01_ユーザー管理モジュールで設定）。

### 3.2. 各種勤怠フラグの管理
 
#### フラグ定義と労働時間への影響
 
同日に設定できるフラグは **1 種類のみ**（排他制御）。UI 上で他フラグを選択すると現在のフラグがクリアされ、確認ダイアログを表示する。
 
| フラグ | 識別値 | 労働時間計算への影響 | 事業別割り当て要否 |
|---|---|---|---|
| フラグなし（通常出勤） | `none` | 実打刻から算出 | 必要（打刻がある日） |
| 有給 | `paid_leave` | **所定労働時間を付与**（実打刻があっても所定時間を優先） | 自動で `is_default_for_paid_leave = 1` の事業に割り当て（手動変更可） |
| 時間休 | `hourly_leave` | `実打刻時間 ＋ 時間休時間数` | 必要 |
| 半日休（午前） | `half_day_am` | `実打刻時間 ＋ 所定時間の50%` | 必要（実打刻分） |
| 半日休（午後） | `half_day_pm` | `実打刻時間 ＋ 所定時間の50%` | 必要（実打刻分） |
| 休日出勤 | `holiday_work` | 実打刻から算出 | 必要 |
| 法定振替休 | `legal_substitute` | 労働時間 0（実打刻があっても無視） | 不要 |
| 所定振替休 | `scheduled_substitute` | 労働時間 0（実打刻があっても無視） | 不要 |
 
#### フラグなし・打刻なしの日の扱い
 
- `clock_in` 打刻がなく、かつ勤怠フラグも設定されていない日 = **欠勤（労働時間0）** として集計する。
- フラグ設定・打刻の両方が存在しない日は事業別割り当て不要（欠勤のため）。

### 3.3. 事業別労働時間（時間割）割り当て機能
 
#### 入力の基本単位：「時間帯（開始時刻〜終了時刻）」
 
事業別の割り当ては **「何時間働いたか」ではなく「何時から何時まで従事したか」** を時間帯で入力する。これにより後述のグリッド表示が成立し、監査・請求に耐える記録となる。
 
**休憩時間の扱い（重要）：**
- 休憩は **02_打刻管理モジュールの `break_in`〜`break_out` 打刻から取得**する。スタッフが時間帯入力モーダルで休憩を入力することはない。
- 事業割り当ては「実際に働いた時間帯」のみを対象とし、**休憩の時間帯は飛ばして（谷間として空けて）入力する**。
- 結果として、事業割り当て行の合計時間は「実労働時間（休憩を除いた時間）」と一致する（→ バリデーション条件4）。
**入力例（休憩は打刻由来の谷間として飛ばす）：**
```
白戸 2025/06/10（火）
  打刻：出勤 8:30 ／ 休憩 12:30〜13:30（打刻由来）／ 退勤 17:15
  実労働 7時間45分（= 17:15 − 8:30 − 60分休憩）
 
  行1： 本社業務        8:30 ～ 12:30  （4時間00分）
  ┌─────────────────────────────────┐
  │ 12:30〜13:30 は休憩（打刻由来）→ 事業割り当てなし・グリッドは空白 │
  └─────────────────────────────────┘
  行2： 氷河期支援      13:30 ～ 15:30  （2時間00分）
  行3： 障がい者雇用    15:30 ～ 17:15  （1時間45分）
                                合計 7時間45分 ✓（実労働と一致）
```
 
> **PHP実装時の注意：** 休憩時間帯（上例の 12:30〜13:30）は `wp_attendance_logs` の `break_in`/`break_out` から取得し、グリッド描画時に「事業セルを描かない区間」として扱う。`wp_project_hours` には休憩のレコードを作らない。
 
#### 入力タイミング
 
1. **退勤時のポップアップ（推奨）：** 退勤打刻直後に事業別時間帯入力モーダルを表示する。【後で入力する】ボタンでスキップ可能。
2. **タイムカード画面のグリッドセルからの後入力：** 該当日の「⚠️ 要入力」セルをクリックして入力モーダルを開く。
#### 入力モーダルの仕様
 
- 行追加形式（＋ボタンで行を追加）。各行に以下を入力する。
  - 事業選択（`wp_businesses` プルダウン・必須）
  - 開始時刻（HH:MM 形式・必須）
  - 終了時刻（HH:MM 形式・必須）
  - 時間数（`end_time − start_time` を自動計算して表示・編集不可）
- 保存時に以下のバリデーションを実行する。
#### 時間帯の整合性バリデーション（3条件すべて満たすこと）
 
```
条件1（時系列整合）  ： 各行の start_time < end_time
条件2（範囲内）      ： 全行の時間帯が clock_in 〜 clock_out の範囲内に収まること
条件3（重複なし）    ： 同日の複数行で時間帯が重複していないこと
条件4（合計一致）    ： Σ(end_time - start_time) の合計分数 ＝ 実労働時間（分）
```
 
いずれかの条件を満たさない場合は保存をブロックし、違反内容をメッセージで通知する。
 
#### 有給日の自動割り当て
 
- 有給フラグが設定された日は、`is_default_for_paid_leave = 1` の事業（デフォルト：本社業務相当）に対し、`start_time = 所定開始時刻`・`end_time = 所定終了時刻` で自動割り当てする（`is_auto_assigned = 1` フラグを付与）。
- スタッフが手動で変更・分割することは可能とする。
#### 通常勤務日のデフォルト事業自動割り当て（将来実装・フェーズ未定）
 
> **現時点では未実装。** 必要になったタイミングで実装できるよう、仕様のみここに定義しておく。実装に着手する前に、本セクションの内容を関係者と再確認すること。
 
**目的：** 単一の事業にほぼ専従する社員について、毎日の事業別時間入力の手間を減らす。
 
**前提：** 01_ユーザー管理モジュールの社員属性に `default_business_id`（デフォルト事業。`wp_businesses.business_id` を参照）を追加する（→ 01_user_management.md §3.3①）。未設定（`NULL`）の社員は本機能の対象外とし、従来どおり手動入力を必須とする。
 
**動作（案）：**
- 対象：有給フラグの日を除く、事業別時間の入力が必要な通常勤務日（§3.2「フラグなし・打刻なしの日の扱い」の対象日）。
- 退勤打刻が完了し実労働時間が確定した時点で、`start_time = clock_in`・`end_time = clock_out`（休憩時間帯は既存仕様どおり除く。休憩が複数回ある場合は複数行に分割する）で `default_business_id` の事業へ自動割り当てする（`is_auto_assigned = 1` を付与。有給日の自動割り当てと同じ考え方）。
- スタッフは自動割り当てられた内容を、複数事業を掛け持ちした日など必要に応じて手動で修正・分割できる（有給日の自動割り当てと同様、上書きを妨げない）。
- 月次提出時のブロック制御（次項）では、自動割り当て済みの日も「入力済み」として扱う。
 
**保留理由・決めていないこと（実装時に要確認）：**
- 自動割り当てのタイミング（退勤打刻の都度か、月次勤務表を開いたタイミングでまとめてか）。
- 複数事業を恒常的に掛け持ちする社員（`default_business_id` 1件では表現できないパターン）の扱い。
- 事業別時間の入力タイミング（§3.3「入力タイミング」）で既に案内している「退勤時のポップアップ」との共存方法（自動割り当て済みなら省略するか、確認だけさせるか）。
#### 月次提出時のブロック制御
 
提出操作時に、事業別割り当てが必要な全日（出勤フラグあり日・休日出勤日など）について未入力日がないかをチェックする。**1 日でも未割り当てが残っている場合は提出ボタンをグレーアウトし、未割り当て日数と日付一覧を提出ボタン直上に表示する。**

### 3.4. 3段階の締め・提出・承認フロー
 
#### ステータス定義
 
| ステータス | `status` 値 | 説明 |
|---|---|---|
| 未提出 | `draft` | スタッフが編集中。初期状態。 |
| 提出済 | `submitted` | スタッフが「確定して提出」を実行。スタッフの編集がロックされる。 |
| チェック者差し戻し | `rejected_by_checker` | チェック者が差し戻し。スタッフの編集ロックが解除される。 |
| チェック済 | `checked` | チェック者（第1承認者）が承認。 |
| 管理者差し戻し | `rejected_by_admin` | 最終管理者が差し戻し。スタッフの編集ロックが解除される。 |
| 確定 | `confirmed` | 最終管理者（第2承認者）が承認。完全ロック。 |
 
#### ステータス遷移図
 
```
draft → submitted → checked → confirmed
          ↑↓差戻し      ↑↓差戻し
    rejected_by_checker  rejected_by_admin
```
 
差し戻し時（いずれのステータスからでも）：
- `status` を差し戻しステータスに更新
- `rejection_comment`（必須）を `wp_monthly_summary` に記録
- `last_rejected_by` / `last_rejected_at` を記録
- スタッフの編集ロックを解除し、修正・再提出できる状態に戻す
- 再提出時は `status = submitted` にリセットし、チェック者から審査がやり直し（フルリスタート）
#### 操作権限マトリクス
 
| 操作 | general_staff | approver | hr_admin | administrator |
|---|---|---|---|---|
| 提出 | 自身のみ可 | 自身のみ可 | 全員分可 | 全員分可 |
| チェック者承認・差し戻し | 不可 | 担当者のみ可 | 全員分可 | 全員分可 |
| 最終承認・差し戻し | 不可 | 不可 | 全員分可 | 全員分可 |
| 確定後の閲覧 | 自身のみ | 担当者のみ | 全員分 | 全員分 |
 
**自己承認の禁止：** チェック者・最終管理者は、自身が提出者である月次データを承認できない（01_ユーザー管理モジュールの `first_approver_id` 自己設定禁止制約と連動）。
 
---
 
### 3.5. 月次データスナップショット（給与条件の固定）
 
**スナップショット取得タイミング：最終管理者が `confirmed`（最終承認）を実行した瞬間のみ。**
 
取得内容（`wp_monthly_summary` の各カラムへ書き込み）：
1. `snapshot_base_salary`：`wp_salary_history` から `effective_date <= 対象月末日` の最新値
2. `snapshot_allowances`：`wp_user_allowances` から `effective_date <= 対象月末日` の各手当最新値を JSON 形式で記録
**差し戻し時の処理：** `confirmed` から `rejected_by_admin` にステータスが戻ることはない（最終承認後の差し戻し操作は UI 上提供しない）。差し戻しは `checked` 以前の状態でのみ実行可能。
 
これにより、翌月以降に基本給の昇給・手当の削除があっても、確定済み月度の給与条件データは不変となる。

## 4. 画面要件（UI/UX）
 
### 4.1. スタッフ向け：月次勤務表（タイムカード）画面（`/portal/attendance/`）
 
#### 画面の基本構造
 
現行 Excel の勤務予定表と**完全に同等のグリッド形式**でブラウザ上に表示する。
 
```
       │  1(月) │  2(火) │  3(水) │ … │ 31(水) │  事業別集計
───────┼────────┼────────┼────────┼───┼────────┼──────────────
8:00  │ [本社] │        │ [本社] │   │        │  本社業務  124.0h ■
9:00  │ [本社] │ [氷河] │ [本社] │   │        │  氷河期     40.0h ■
10:00 │ [本社] │ [氷河] │        │   │        │  障がい者    4.5h ■
…     │        │        │        │   │        │  …
```
 
- **縦軸（行）：** 時間帯スロットを **15分単位**で分割する（例：8:00〜21:45）。表示開始・終了時刻はプラグイン設定で変更可能。
  - **罫線の階層表示：** 毎正時（:00）は太い濃色の罫線＋時刻ラベル、:30 は中間色の罫線、:15・:45 は細い淡色の罫線とする。これにより「1時間のまとまり」を視認しつつ15分刻みであることが伝わる。
- **横軸（列）：** 月内の日付（1〜末日）。土曜は青系・日曜/祝日は赤系で列を区別。列幅は全日付で統一し、画面に収まらない場合は横スクロールとする（時刻列は左に固定）。
- **各セル：** `wp_project_hours` の `start_time`〜`end_time` に含まれる15分スロットを、当該事業の `color_code` で塗り色表示する。事業ブロックの先頭スロットにのみ事業名を表示する。
  - **打刻の丸め：** 出勤は切り上げ（roundUP）、退勤は切り下げ（roundDOWN）方向に15分丸めし、塗り範囲を内側に寄せる。
  - **休憩時間帯：** 打刻（`break_in`〜`break_out`）由来の休憩区間は事業セルを描かず空白とする（→ 3.3節）。
  - **有給日：** 時間帯の色塗りは行わず、セルに「有給」表示のみとする。所定労働時間（`scheduled_work_hours`）を量として `is_default_for_paid_leave = 1` の事業の集計に算入する（時刻では描画しない）。
- **右端／右パネル：** 月次の事業別合計時間と事業カラーのサマリーをグリッド外の独立パネルとして表示する（sticky 固定）。
- **事業カラー：** 各事業の表示色は事業マスタ（`wp_businesses.color_code`）に従う。黄色系など明度の高い背景色の事業は、セル内テキストを濃色にして可読性を確保する。
#### セルへの編集操作
 
- 未割り当て（白紙）のある日のセルをオレンジでハイライトし、「⚠️ 要入力」を表示する。
- **入力済み・未入力いずれのセルも、ダブルクリックで時間帯入力モーダル（→ 3.3節）を開く**（シングルクリックでは開かず、誤操作を防ぐ）。グリッド上部のヒントバーに、ホバー中の日付と「ダブルクリックで編集できる」案内を表示する。
- 入力が完了したセルは即座にグリッド上で色付き表示に更新される（Fetch API による非同期更新）。
#### 日次サマリー行
 
グリッドの最上部に日次サマリー行を設け、以下を表示する。
 
- 出勤時刻 / 退勤時刻（打刻由来）
- 勤怠フラグ（プルダウン選択。ドロップダウン矢印は非表示にして文字との重なりを防ぐ）
- 交通費アイコン行（`🚗`：当該日の04_交通費・車両借り上げ入力モーダルへのショートカット）。フラグ行とは罫線で区切って独立した行とする。
#### 画面統合（スタッフ向け・タブ構成）
 
スタッフの月次提出画面は、勤怠・交通費・車両借り上げ・集計表を**1画面のタブ**で統合する。
 
- 共通ヘッダー（対象月ナビ・提出ステータス・「まとめて提出」ボタン）はタブの外に置く。
- タブ：**勤怠 / 交通費 / 車両借り上げ / 集計表** の4つ。
- 提出は3点（勤怠＋交通費＋車両借り上げ）をまとめて行い、月次ワークフローのステータスで同時にロックする（→ 04モジュール 1節と連動）。
- 管理者の承認・集計画面も同じタブ構成（勤怠 / 交通費 / 車両借り上げ）とし、スタッフ画面とレイアウトを統一する。
#### 集計表タブ（月次総括表）
 
給与計算の基礎となる月次総括表を表示する。事業名の増減に対応するため、交通費・車両借り上げの事業別内訳は事業マスタ（`wp_businesses`）から動的生成する。
 
| 区分 | 項目 | データ源 | 編集 |
|---|---|---|---|
| 基本情報 | 社員番号・氏名 | 01モジュール | 読取専用 |
| 給与・手当 | 基本給・各種手当 | スナップショット（`snapshot_base_salary` / `snapshot_allowances`） | 読取専用（自動表示） |
| 交通費 | 事業別内訳＋合計 | 04モジュール（事業別集計） | 読取専用 |
| 車両借り上げ | 事業別内訳＋合計 | 04モジュール（事業別集計） | 読取専用 |
| 勤務サマリ | 出勤日数・総労働時間 | 本モジュール集計 | 読取専用 |
| 勤怠サマリ | 有給・時間休・欠勤・遅刻早退・在宅日数 | 本モジュール集計 | 読取専用 |
| 総支給額 | 基本給＋手当＋交通費＋車両借り上げ | 上記の合算 | 自動計算 |
 
- **給与・手当は手入力ではなく従業員マスタ由来の自動表示**とする。基本給は `wp_salary_history`、各手当は `wp_user_allowances`（手当マスタ × 個人金額）の月次スナップショット値を表示する。修正は01モジュールの給与・手当設定で行う。
#### ワークフロー制御
 
- ステータスが `submitted` 以降はグリッド全セルを読み取り専用（クリック不可）にする。
- 差し戻し中（`rejected_by_checker` / `rejected_by_admin`）は差し戻しコメントを画面上部に赤色で表示し、編集を再開できる。

### 5.4. `wp_project_hours`（事業別時間実績）
 
**事業への割り当ては「時間帯（開始〜終了）」単位で記録する。** `minutes` は `end_time − start_time` の算出値として保持し、集計クエリの高速化に使用する。
 
```sql
CREATE TABLE wp_project_hours (
    id               INT AUTO_INCREMENT PRIMARY KEY,
    user_id          BIGINT UNSIGNED NOT NULL,
    work_date        DATE            NOT NULL,
    business_id      INT             NOT NULL,   -- wp_businesses.business_id
    start_time       TIME            NOT NULL,   -- 従事開始時刻（例: '08:30:00'）
    end_time         TIME            NOT NULL,   -- 従事終了時刻（例: '12:30:00'）
    minutes          INT             NOT NULL,   -- 算出値: TIMESTAMPDIFF(MINUTE, start_time, end_time)
    is_auto_assigned TINYINT(1)      NOT NULL DEFAULT 0, -- 1 = 有給日の自動割り当て
    created_at       DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at       DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_date     (user_id, work_date),
    INDEX idx_business_date (business_id, work_date)
);
```
 
**制約・バリデーション（アプリケーション層で実施）：**
- 同一 `user_id` + `work_date` の複数行で `start_time`〜`end_time` が重複しないこと。
- `start_time` < `end_time` であること。
- 全行の時間帯が当日の `clock_in`〜`clock_out`（02モジュール）の範囲内に収まること。
- `Σ minutes` が当日の実労働時間（`wp_daily_attendance.actual_minutes`）と一致すること。
### 5.5. `wp_monthly_summary`（月次確定テーブル）
 
```sql
CREATE TABLE wp_monthly_summary (
```

## 7. 非機能要件
 
### 7.1. 残業計算の週次集計タイミング
 
週次法定外残業（週40時間超）の計算は、月次締め対象期間の各週を対象に、日曜日始まりで集計する。月またぎの週は月次締め期間の対象日数のみをカウントする。
 
### 7.2. 弥生 CSV の文字コード
 
出力は **Shift-JIS / CR+LF** 形式とする。弥生給与計算のバージョンアップによりフォーマットが変更された場合は、プラグイン設定にてカラムマッピングを変更できる拡張ポイントを設ける。
 
### 7.3. データ保持・ロック
 
- `confirmed` ステータスになった月度の `wp_daily_attendance`・`wp_project_hours`・`wp_monthly_summary` は、いかなるロールからも更新・削除不可とする。
- 法定の書類保存義務（5年）に従い、確定済みデータの削除機能は管理画面に設けない。
