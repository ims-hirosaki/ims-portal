# 要件定義書：04_交通費・車両借上げ申請モジュール (04_travel_expenses.md)
 
## 1. 目的・概要
 
本モジュールは、従業員の日々の通勤交通費および業務中のマイカー移動に伴う「車両借上げ費」を管理・集計する機能である。
 
**通勤費にも事業別割り当てが必要な理由（業務背景）：**
通勤交通費は「その日どの事業のために出勤したか」によって、負担する事業が変わる。例えば、通常は本社業務のための出勤だが、特定日に氷河期支援事業のみに従事する場合は、その日の通勤費は氷河期支援事業から支出される。車両借上げ費（業務中の移動）も同様に、移動した目的の事業に紐づけて記録・集計する必要がある。これにより、月次で「各事業に対して通勤・移動費がいくら発生したか」を事業ごとに正確に算出し、委託元への請求根拠とする。
 
**他モジュールとの役割分担（重要）：**
 
| 移動・経費の種別 | 管理モジュール |
|---|---|
| 通勤（マイカー往復） | **本モジュール（04）** で自動計算 |
| 業務中のマイカー移動（訪問・直行直帰） | **本モジュール（04）** でスタッフが入力 |
| 公共交通機関の移動費（実費） | **05_稟議モジュール** の経費精算申請 |
| 出張時の宿泊費・新幹線・飛行機 | **05_稟議モジュール** の出張申請・経費精算 |
 
この区分により、マイカー使用によるすべての走行費が本モジュールで一元集計され、二重計上が発生しない構造とする。
 
**交通費と車両借り上げの会計上の区別（重要・ページ分離の根拠）：**
 
両者は計算式（距離×単価）こそ共通だが、会計上の性質が異なるため、**計上先のページ・データを分離して管理する**。
 
| 区分 | 性質 | 会計上の扱い |
|---|---|---|
| 交通費（ガソリン代） | 通勤・移動の**実費精算** | 旅費交通費。本人に実費が戻る |
| 車両借り上げ | 自家用車を業務使用させる**対価（手当）** | 賃借料・手当。事業ごとの請求根拠として厳密管理が必要 |
 
- **交通費ページ：** 1日〜月末を時系列で一覧表示し、事業を色分けで区別する（事業ごとの区切り・小計は設けない）。
- **車両借り上げページ：** 事業ごとに区切って明細を表示し、事業別の小計を出す。事業フィルタで特定事業に絞り込める。
- スタッフの入力モーダルは通勤・借り上げのセクション分けを維持するが、**入力結果は交通費／車両借り上げの別テーブル・別ページに振り分けて計上する**。
本モジュールには独自の「提出」ボタンを設けず、**03_勤怠管理モジュール**の月次提出フローと完全同期してデータをまとめて処理する（勤怠＋交通費＋車両借り上げを月次で同時提出・同時ロック）。管理者には、交通費の事業別集計・車両借り上げの事業別集計・総支給額が2本立てのサマリとして届く。
 
**プラグイン構成（PHP実装の前提）：**
 
本モジュール（04_交通費・車両借上げ）は、**03_勤怠管理モジュールと同一の WordPress プラグイン内の別モジュール**として実装する。プラグインを分割せず、03と1つのプラグイン内に同居させる。
 
- 提出フロー・月次ステータス（`wp_monthly_summary`）・事業マスタ（`wp_businesses`）は03と共有する。本モジュールはこれらを新規に持たず、03が定義したものを参照する。
- 機能ディレクトリ（例：`includes/travel/`）で03と論理分割するが、プラグイン本体・有効化フックは共通とする。
- 03の提出・承認・差し戻し・確定の各操作と同一フック内で、本モジュールの `wp_travel_expenses` のロック／解除を行う（プラグイン境界をまたがない）。

## 2. マスター設定要件
 
### 2.1. ガソリン単価変更と適用月指定
 
メニュー階層：`設定 > 交通費設定 > ガソリン単価変更履歴`
 
`hr_admin` / `administrator` のみが操作できる専用画面を設ける。
 
#### 操作フロー
 
1. 管理者が新しい単価（円/km）と **「適用開始月（YYYY-MM）」** を入力して保存。
2. システムは以下のレコードを一括再計算する：
   - 対象：`work_date` が適用開始月以降のすべての `wp_travel_expenses` レコード
   - 除外：`wp_monthly_summary.status = 'confirmed'`（確定済み）の月度に属するレコード
   - 処理内容：各レコードの `unit_price` を新単価で更新し、`amount` を再計算して保存する。
3. 再計算対象件数と影響月を確認ダイアログで表示し、管理者が「実行」を確定することで処理を行う。
#### 単価変更履歴の保持
 
過去の単価変更履歴（変更前単価・変更後単価・適用開始月・変更者・変更日時）を記録し、管理画面で一覧表示する。これにより「いつ、誰が単価を変更したか」を追跡できる監査証跡とする。
 
---
 
### 2.2. 距離の小数処理設定
 
メニュー階層：`設定 > 交通費設定 > 計算ルール`
 
距離の端数処理方法を選択する。**他組織でも使い回せるよう、組織ごとに設定可能とする。**
 
| 設定項目 | 選択肢 | デフォルト |
|---|---|---|
| 距離の小数点処理 | 切り捨て（floor）/ 四捨五入（round）/ 切り上げ（ceil） | 切り捨て |
 
**計算順序（重要）：**
 
```
① 距離を設定ルールで丸める（例：12.4km → 切り捨て → 12km）
② 金額 = 丸めた距離 × 単価（さらに金額の小数を切り捨て）
```
 
- 距離を**先に**丸めてから金額を計算する。金額を計算してから丸めるのではない。
- 例（単価27.0円/km）：12.4km → 切り捨て12km × 27.0 = 324円 ／ 四捨五入12km = 324円 ／ 切り上げ13km = 351円
- この設定は交通費・車両借り上げの双方に共通で適用する。

## 3. 機能要件
 
### 3.1. 通常の通勤交通費（通勤手当）の自動計算
 
#### 自動生成トリガー
 
**02_打刻管理モジュール**の `wp_attendance_logs` を参照し、以下の条件に基づいて通勤交通費レコードを自動生成する。月次の締め対象期間（03_勤怠管理モジュールの締め日設定に従う）の各日に対して処理する。
 
| 条件 | 処理 |
|---|---|
| `clock_in` 打刻がある日 | 通常通勤レコードを自動生成（金額を計算） |
| 03モジュールの勤怠フラグが `paid_leave`（有給）の日 | `amount = 0`・`is_zero_suppressed = 1` で生成 |
| 03モジュールの勤怠フラグが `legal_substitute`（法定振替休）の日 | `amount = 0`・`is_zero_suppressed = 1` で生成 |
| 03モジュールの勤怠フラグが `scheduled_substitute`（所定振替休）の日 | `amount = 0`・`is_zero_suppressed = 1` で生成 |
| `half_day_am`（半日休・午前）または `half_day_pm`（半日休・午後）の日 | 出勤した事実があるため**全額支給**として通常通りのレコードを生成 |
| `clock_in` 打刻がなく、勤怠フラグも `none` の日（欠勤） | レコードを生成しない（欠勤日は自動生成対象外） |
 
#### 通常通勤の計算式
 
```
片道距離 (km) = commute_one_way_km（01_ユーザー管理のユーザーメタより取得。片道で管理）
適用距離 (km) = commute_type が 'round_trip' なら 片道距離 × 2、'one_way' なら 片道距離
丸め距離 (km) = 適用距離を距離小数処理設定（→ 2.2節）で丸める
支給金額 (円) = FLOOR( 丸め距離 × gasoline_unit_price )
```
 
> **フィールド名の整合（PHP実装時の注意）：** 通勤距離は01_ユーザー管理モジュールで **`commute_one_way_km`（片道）** として管理する（直行直帰対応のため往復ではなく片道で保持）。往復の場合は実装側で × 2 する。`commute_round_trip_km` という往復フィールドは使用しない。
 
計算に使用した `unit_price` と `distance_km` は、生成時にレコードへコピーして保持する（→ ガソリン単価変更時の再計算で参照・更新される）。
 
#### 通勤費の事業別割り当て（必須）
 
通勤費は「その日どの事業のために出勤したか」を `business_id` として必ず設定する。**`business_id` が未設定の通勤レコードがある場合、月次提出をブロックする**（→ 3.5節参照）。
 
**自動サジェストのロジック：**
 
自動生成時点では `business_id = NULL` とし、以下のルールで自動サジェストを提示する。
 
| 条件 | サジェスト動作 |
|---|---|
| その日の `wp_project_hours` に1事業のみ登録されている | その事業を自動セット（`business_id` を自動埋め）|
| 複数事業が登録されており、最多時間の事業が明確 | 最多時間の事業を初期値としてプルダウンにセット（編集可） |
| 複数事業が同時間で並んでいる / 未登録 | プルダウンを「未設定（要選択）」として警告表示 |
 
- サジェストは参考値であり、スタッフは常にプルダウンから手動変更できる。
- `wp_project_hours` の入力後に自動再サジェストが行われる（ページ再読み込み時に更新）。
**入力 UI：**
 
交通費一覧画面（→ 4.1節）の各通勤行に「事業」プルダウンを設け、`wp_businesses` の有効な事業一覧から選択できるようにする。選択すると行の「色」セルが当該事業のカラーで塗られる。
 
#### 05_稟議モジュールからの有給承認連動
 
**05_稟議モジュール**で有給休暇申請が最終承認（`confirmed`）された場合、対象日の `wp_travel_expenses` の通勤レコードを `amount = 0`・`is_zero_suppressed = 1` に自動上書きする。
 
- 対象日のレコードがすでに存在していた場合（スタッフが手動変更済みを含む）：上書きする。
- 上書きされたことをスタッフのポータル画面に「有給申請が承認されたため、○月○日の通勤交通費を0円に変更しました」と通知する。

### 3.2. 車両借上げ費の入力機能
 
業務中のマイカー移動（訪問・直行直帰・直行直帰）について、スタッフが日付ごとに走行区間を入力する。
 
#### 1日の入力方式（複数行入力）
 
1日の移動は **区間ごとに1行ずつ** 追加する形式を基本とする。例：
 
| 行 | 出発地 | 目的地 | 距離(km) | 往復 | 事業 | 金額 |
|---|---|---|---|---|---|---|
| 1 | 自宅 | 有限会社安田保険_弘前 | 8.5 | ✓ | 氷河期事業（緑） | 357円 |
| 2 | 有限会社安田保険_弘前 | 本社 | 8.5 | ─ | 本社業務（青） | 178円 |
 
**往復ボタン（× 2 機能）：**
- 各行に「往復」チェックボックスを設ける。
- チェックをオンにすると、入力した距離（片道）を 2 倍に換算して金額を計算する。
- DB には入力した片道距離を `distance_km` に保存し、`is_round_trip = 1` フラグで往復換算を識別する。
#### 入力項目の定義
 
| 項目 | 型 | 説明 |
|---|---|---|
| 移動区間（出発地） | TEXT | テキスト入力（例：自宅、本社、訪問先名） |
| 移動区間（目的地） | TEXT | テキスト入力 |
| 距離 (km) | DECIMAL | 片道の実移動距離。0 より大きい値を必須とする |
| 往復フラグ | BOOLEAN | ON = 距離を 2 倍で計算。OFF = 片道のみ |
| 紐付け事業 | SELECT | **03_勤怠管理モジュール**の事業マスタ（`wp_businesses`）から選択。必須 |
 
#### ガソリン代の自動算出
 
```
実距離 (km) = distance_km × (is_round_trip ? 2 : 1)
借上げ金額 (円) = 実距離 × unit_price（入力時に01モジュールのユーザーメタより取得してレコードに保存）
```

### 3.3. 直行直帰時の通常通勤相殺（片道変更）／往路・復路の事業分割
 
#### ① 片道変更（直行直帰）
 
「往路は現場へ直行・復路は本社へ帰還」のように、通常の通勤往復が発生しないイレギュラーな場合に対応する。
 
- 当日の自動生成された通常通勤レコードに、`commute_type` プルダウン（「往復」／「片道」）を設ける。
- **「片道」を選択した場合：**
  - `commute_type = 'one_way'` に更新し、`amount = FLOOR((片道距離) × unit_price)` で再計算する。
  - 距離が変わる移動（午後にイベント会場へ移動して直帰など）は、通勤を「片道」にしたうえで、会場への移動・直帰を**車両借り上げ**で登録する（役割分担：同じ道の往復で事業だけ違う場合は下記②、距離が変わる移動は車両借り上げ）。
- このプルダウンはスタッフが自由に変更できる（ただし `confirmed` 後はロック）。
#### ② 往路・復路の事業分割
 
「朝は本社業務のために出社（往路＝本社）、夕方は氷河期支援業務を終えて帰宅（復路＝氷河期）」のように、**同じ通勤経路でも往路と復路で従事事業が異なる**場合に対応する。
 
- 通勤セクションに「往路・復路で事業を分ける」トグルを設ける。
- **オフ（デフォルト）：** 往復を1レコードとして扱い、1事業を紐づける（通常運用）。
- **オン：** 通勤を往路・復路の2レコードに分割し、それぞれに事業を紐づける。
  - 往路距離 = 復路距離 = `commute_one_way_km`（片道距離を半分ずつ）。
  - 各レコードは `commute_type = 'one_way'` として保存し、別々の `business_id` を持つ。
- 往路・復路で**距離が異なる**場合（別拠点に寄るなど）は、このトグルではなく車両借り上げで登録する。

### 3.4. 事業別自動集計（監査対策）
 
月末時点で、以下の2つのデータソースを事業IDで集計し、「今月どの事業に対して総額いくらの交通費・借上げ費が発生したか」を事業別に自動集計する。
 
```
事業別合計 =
  ① 03_wp_project_hours の業務時間（時間単位の人件費計算は給与計算ソフトに委ねる）
  ② 04_wp_travel_expenses の amount（当該事業に紐づく交通費・借上げ費）
```
 
事業別集計は画面表示時に動的に計算し、`confirmed` 後は `wp_monthly_summary` のスナップショットに含めて固定する。
 
---
 
### 3.5. 勤怠提出フローとの完全統合
 
本モジュール専用の「提出」ボタンは設けない。以下の通り **03_勤怠管理モジュール**のワークフローと連動する。
 
| 03モジュールのステータス変化 | 04モジュールの挙動 |
|---|---|
| `draft` → `submitted`（スタッフ提出） | 当該月度の `wp_travel_expenses` 全レコードを読み取り専用にロック |
| `submitted` → `rejected_by_checker`（差し戻し） | ロックを解除し、スタッフが編集を再開できる |
| `rejected_by_admin` | ロックを解除し、スタッフが編集を再開できる |
| `checked` → `confirmed`（最終承認） | 完全ロック。以降いかなる権限でも編集不可 |

## 4. 画面要件（UI/UX）
 
### 4.1. スタッフ向け：交通費・車両借り上げ入力画面
 
スタッフの月次提出画面は**03_勤怠管理モジュールのタイムカード画面と統合**し、1画面のタブ（勤怠 / 交通費 / 車両借り上げ / 集計表）で切り替える（→ 03モジュール 4.1節）。03_勤怠グリッドの「🚗」アイコン経由で当該日のモーダル入力もできる。
 
#### 交通費タブ（ガソリン代・時系列表示）
 
1日〜月末を時系列で一覧表示する。**事業ごとの区切り・小計は設けず**、各行を事業カラーで色分けして区別する。
 
| 列 | 内容 |
|---|---|
| 月日 | 日付・曜日。土日・休日は背景を区別。休日は「休日」と淡色表示 |
| 内容 | 「自宅〜本社 往復／片道」などの経路テキスト |
| 距離(km) | 丸め後の適用距離 |
| 金額 | 支給金額（円） |
| 事業 | 事業カラードット＋事業名。未設定は「⚠️ 未設定」表示。行の左端も事業カラーバーで色分け |
| 操作 | 「✏️ 編集」アイコン → 当該日の入力モーダルを開く |
 
- 有給・振替休日で通勤費が 0 円の行は薄いグレーで「※有給（0円処理）」等のラベルを付ける。
- 右パネルに交通費の事業別集計（参考）＋月次合計を表示する。
- 末尾に交通費の月次合計を表示する。
#### 車両借り上げタブ（手当・事業別表示）
 
業務中のマイカー移動を**事業ごとに区切って表示**し、事業別の小計を出す。
 
- 事業フィルタ（「すべての事業 / 各事業」のチップ）で特定事業に絞り込める。
- 各事業グループの見出し（事業カラー＋事業名）の下に明細行を並べ、グループ末尾に小計を表示する。
- 右パネルに車両借り上げの事業別集計＋合計を表示する。
#### 集計表タブ（月次総括表）
 
→ 03_勤怠管理モジュール 4.1節「集計表タブ」を参照。交通費・車両借り上げの事業別内訳は本モジュールの集計値を提供する。
 
#### 入力モーダル（日別）
 
各日の「✏️ 編集」またはタイムカード画面の「🚗」アイコンから開くモーダルの構成：
 
1. **通勤セクション：** 往復距離・単価・金額を表示。`commute_type` プルダウン（往復／片道）で相殺変更可。「往路・復路で事業を分ける」トグル（→ 3.3節②）。**事業プルダウン**（必須・自動サジェスト付き）。通勤費は自動でデフォルト値（距離・単価・金額・サジェスト事業）が埋まった状態で開く。
2. **車両借上げセクション：** 借上げ行の一覧表示。【区間を追加】ボタンで区間を入力。各行に出発地・目的地・距離・往復チェック・事業選択・金額（自動計算）を表示。デフォルト値なし・空欄スタート。
3. **日次合計：** 通勤 ＋ 借上げの合計金額・合計距離を右下に表示。

### 4.2. 管理者向け：事業別経費確認・承認画面（wp-admin 内）
 
- 月・社員を指定して交通費明細を表示する。
- 日ごとの通勤交通費・車両借上げ費の距離と金額、および事業カラーによる色分けをグリッドで表示（Excel フォーマットと同等の視認性）。
- 承認画面では 03_勤怠管理モジュールのワークフロー画面と同一ページ内でタブ切り替えにより勤怠・交通費を一括確認できる構成とする。
- **ダウンロード機能（`confirmed` データのみ）：**

## 5. データベース設計（独自テーブル）
 
### 5.1. `wp_travel_expenses`（交通費・借上げ明細）
 
```sql
CREATE TABLE wp_travel_expenses (
    id                INT AUTO_INCREMENT PRIMARY KEY,
    user_id           BIGINT UNSIGNED NOT NULL,       -- 01 wp_users.ID を参照
    work_date         DATE            NOT NULL,
    expense_type      ENUM('commute','vehicle_rental') NOT NULL,
    -- 通勤レコード専用
    commute_type      ENUM('round_trip','one_way') DEFAULT 'round_trip',
    -- 車両借上げレコード専用
    route_from        VARCHAR(200)    DEFAULT NULL,   -- 出発地
    route_to          VARCHAR(200)    DEFAULT NULL,   -- 目的地
    is_round_trip     TINYINT(1)      NOT NULL DEFAULT 0, -- 1 = 往復（distance_km × 2で計算）
    -- 共通フィールド
    business_id       INT             DEFAULT NULL,   -- 03 wp_businesses.business_id を参照
                                                      -- ※ commute・vehicle_rental 両方に適用。
                                                      --   通勤費はその日の従事事業を設定（必須）。
                                                      --   未設定（NULL）は月次提出をブロックする。
    distance_km       DECIMAL(7,2)    NOT NULL DEFAULT 0, -- 通勤：往復距離(km)。借上げ：片道距離(km)
    unit_price        DECIMAL(6,2)    NOT NULL,       -- 適用ガソリン単価（生成・再計算時に保存）
    amount            INT             NOT NULL DEFAULT 0, -- 支給金額（円・小数切り捨て）
    -- 管理フラグ
    is_auto_generated  TINYINT(1)     NOT NULL DEFAULT 0, -- 1 = 自動生成（通勤）
    is_zero_suppressed TINYINT(1)     NOT NULL DEFAULT 0, -- 1 = 0円処理（有給日等）
    note              TEXT            DEFAULT NULL,
    created_at        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_date     (user_id, work_date),
    INDEX idx_business_date (business_id, work_date),
    INDEX idx_expense_type  (expense_type, work_date)
);
```
 
**計算ロジックの参照：**
 
```
-- commute レコード
amount = FLOOR(
    (commute_type = 'round_trip' ? distance_km : distance_km / 2)
    × unit_price
)
 
-- vehicle_rental レコード
amount = FLOOR(
    distance_km × (is_round_trip = 1 ? 2 : 1) × unit_price
)
```

## 7. 非機能要件
 
### 7.1. データの整合性保証
 
- `vehicle_rental` レコードの `business_id` は必須とし、`NULL` での保存を禁止する。事業が未選択のまま保存しようとした場合はバリデーションエラーを返す。
- `commute` レコードは同一ユーザー・同一 `work_date` に 1 件のみ許容する（アプリケーション層で制御）。
- ガソリン単価の再計算処理は、`confirmed` 月度のデータを一切変更しないことをアプリケーション層のトランザクションで保証する。
### 7.2. 確定後のロック
 
- `wp_monthly_summary.status = 'confirmed'` の月度に属する `wp_travel_expenses` レコードは、すべてのロールからの更新・削除を拒否する（REST API・管理画面双方で権限チェックを徹底）。
### 7.3. データ保持
 
- 労働基準法の保存義務（5年）に従い、確定済みレコードの削除機能は管理画面に設けない。
