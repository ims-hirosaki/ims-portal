# 連携提案書：06_Google Workspace 連携案 (06_google_workspace_integration.md)
 
## 1. 目的・概要
 
本文書は、WordPress ベースの社内勤怠・交通費・稟議システム（01〜05モジュール）と、社内で運用中の **Google Workspace** を効率的に連携させるための提案をまとめたものである。
 
Google Workspace との連携により、以下の価値を実現する。
 
- **操作の一元化：** 社員が使い慣れた Google のツール群と本システムのポータルを自然につなぎ、二重入力・二重管理を排除する。
- **リアルタイム性：** 承認・確定イベントを Google Calendar・Chat・Drive に即時反映し、口頭・メールによる連絡コストを削減する。
- **データの可視化：** 確定済み勤怠・経費データを Looker Studio でダッシュボード化し、経営判断を支援する。
- **管理の自動化：** ユーザーライフサイクル（入社・退社）を Google Admin Console と同期し、アカウント管理の二重作業をゼロにする。

### 6.1. Google SSO（シングルサインオン）【Tier 1】
 
#### 概要
 
社員が `@ims-hirosaki.com` の Google アカウントで本システムのフロントエンドポータル（`/portal/`）にログインできる仕組みを導入する。WordPress の独自パスワード管理を廃止し、認証を Google に委譲する。
 
#### 実装方針
 
- WordPress 側で **WP REST API ＋ Google OAuth 2.0** のカスタム認証エンドポイントを実装する（または `Google Workspace Login` 系プラグインを活用）。
- ログインフロー：
  1. `/portal/login/` にアクセス → 「Google でログイン」ボタン
  2. Google の OAuth 同意画面へリダイレクト
  3. 認証成功後、Google から返却されるメールアドレスを `wp_users.user_email` と突合してセッションを発行
  4. 対応するユーザーが存在しない場合はログイン拒否（自動アカウント作成はしない）
- **ドメイン制限：** `@ims-hirosaki.com` のアカウントのみを許可し、個人 Gmail からのログインを拒否する。
- `wp-admin` へのアクセスは `hr_admin` / `administrator` ロールのみ許可し、これらのロールも Google SSO を経由してログインする。
#### 既存設計との変更点
 
- 01_ユーザー管理モジュールの「ログイン画面（`/portal/login/`）」を、WordPress 標準フォームから Google OAuth フローに差し替える。
- WordPress 側のパスワードリセット機能は使用しなくなるため、パスワード関連 UI を非表示にする。
- 退職処理時（`employment_status = 退職`）に Google アカウントが無効化されれば、自動的に本システムへのログインも不可になる（SSO のため追加処理不要）。

### 6.2. 承認済み休暇・出張のカレンダー自動同期【Tier 1】
 
#### 概要
 
05_稟議モジュールで有給休暇申請・出張申請が `confirmed`（最終決裁完了）になった瞬間、申請者本人と承認者の Google カレンダーに予定イベントを自動作成する。
 
#### 連動タイミングと内容
 
| トリガー | カレンダーへの書き込み内容 |
|---|---|
| 有給休暇申請 `confirmed` | 申請者のカレンダーに「有給休暇」終日イベントを作成（対象日）。承認者カレンダーにも閲覧専用で共有。 |
| 出張申請 `confirmed` | 申請者のカレンダーに「出張：目的地」イベントを作成（開始日〜終了日）。承認者カレンダーにも閲覧専用で共有。 |
| 上記申請が管理者取消（`cancelled`）| 対応するカレンダーイベントを自動削除する。 |
 
#### 実装方針
 
- Google Calendar API（`events.insert` / `events.delete`）を使用する。
- 05_稟議モジュールの `confirmed` 自動連動処理（4.1節）にカレンダー書き込みをフックとして追加する。
- **認証：** サービスアカウント（Service Account）を作成し、Google Workspace の「ドメイン全体の委任」を設定することで、ユーザー個別の OAuth 同意なしに全社員のカレンダーへ書き込みを可能にする。
- カレンダーイベントの `description` に本システムの申請詳細 URL を含め、クリックで稟議画面に遷移できるようにする。
- **ロールバック時：** 管理者取消（`cancelled`）の処理に `events.delete` を追加し、カレンダーイベントも自動削除する。

### 6.3. 領収書・月次 PDF の Drive 自動保存【Tier 1】
 
#### 概要
 
05_稟議モジュールで定義済みの「添付ファイル保存先設定」（`google_drive` 選択時）の具体的な実装仕様を定義する。加えて、03_勤怠モジュールの月次 PDF 出力も Drive の指定フォルダに自動保存する機能を追加する。
 
#### フォルダ構成（Drive 側）
 
```
IMS社内システム/
├── 経費領収書/
│   └── YYYY年/MM月/
│       └── {社員番号}_{氏名}_{申請ID}.pdf（または画像）
└── 月次タイムカード/
    └── YYYY年/MM月/
        └── {社員番号}_{氏名}_タイムカード.pdf
```
 
#### 実装方針
 
- Google Drive API（`files.create`）を使用し、サービスアカウント経由でアップロードする。
- プラグイン設定（`設定 > ファイル保存設定`）で Drive を選択した場合、アップロード先のルートフォルダ ID を入力欄に設定させる。
- 月次タイムカード PDF は、03_勤怠モジュールの `confirmed` 処理に Drive アップロードをフックとして追加する。
- アップロード完了後、Drive のファイル URL を `wp_approval_meta`（領収書）または `wp_monthly_summary`（タイムカード）に記録し、管理画面からリンクで開けるようにする。

### 6.5. 走行距離の自動提案・バリデーション【Tier 2】
 
#### 概要
 
04_交通費モジュールの車両借上げ入力画面で、出発地・目的地を入力した時点で **Google Maps Distance Matrix API** を呼び出し、最短ルートの距離（km）を `distance_km` 欄に自動セットする。手入力ミスや距離の意図的な水増しを防ぐ。
 
#### 機能仕様
 
- 出発地・目的地の両フィールドが入力されたタイミングで非同期で API を呼び出し、推奨距離を `distance_km` に自動入力する（編集可能）。
- 「往復」チェックボックスが ON の場合、API が返す片道距離をそのまま `distance_km` にセットし、UI 上で「往復換算：○○ km」と表示する。
- 手動入力値が API の提案値から **30%以上乖離している場合**（プラグイン設定で変更可能）、保存時に黄色の警告を表示する（保存はブロックしない）。
- **コスト管理：** Distance Matrix API は呼び出しごとに料金が発生するため、同一区間のキャッシュを24時間保持して重複リクエストを削減する（`wp_options` または トランジェントキャッシュを使用）。

### 6.7. Looker Studio 経営ダッシュボード【Tier 2】
 
#### 概要
 
6.6節でエクスポートされた Google Sheets データを Looker Studio のデータソースとして接続し、経営者・人事管理者が現状を一目で把握できるダッシュボードを構築する。本システムの追加実装は 6.6節のエクスポート機能のみで、Looker Studio の設定は Google のノーコードツールで完結する。
 
#### 推奨ダッシュボード構成
 
| レポートページ | 主要グラフ | 対象者 |
|---|---|---|
| 事業別人件費ページ | 事業ごとの月次労働時間（積み上げ棒グラフ）・経費内訳（円グラフ） | 経営者・人事管理者 |
| 残業・勤怠状況ページ | 社員別残業時間ランキング・月推移折れ線グラフ | 人事管理者 |
| 承認フロー進捗ページ | 未提出・提出済・確定の割合（月次）・承認リードタイム | 人事管理者 |
| 交通費分析ページ | 社員別・事業別交通費推移 | 人事管理者 |
 
#### 導入コスト
 
Looker Studio は Google アカウントがあれば無償で利用可能（Google Sheets コネクタも無償）。ダッシュボードの初期構築のみ工数が発生し、以降は自動更新される。

### 6.8. 承認通知の Gmail フォールバック【Tier 2】
 
#### 概要
 
05_稟議モジュールの Google Chat Webhook が 3 回リトライ後も失敗した場合、Gmail API を使ってメール通知を代替送信する。承認フローが通知障害で止まらないことを担保する。
 
#### 実装方針
 
- Gmail API（`users.messages.send`）をサービスアカウントで呼び出し、`noreply@ims-hirosaki.com` からメール送信する。
- メール件名・本文は Google Chat 通知と同等の内容（申請者・種別・対象日・承認画面 URL）とする。
- WordPress の `wp_mail()` + SMTP よりも Gmail API の方が Google Workspace 環境では設定が簡潔で安定する。
- フォールバック発動時はシステムログに記録し、管理者にも通知する。

### 6.9. ユーザーライフサイクルの自動同期【Tier 3】
 
#### 概要
 
Google Admin SDK（Directory API）と連携し、Google Workspace 側でのユーザー追加・停止を本システムの WordPress ユーザー管理に自動反映する。入退社時のアカウント管理における二重作業を排除する。
 
#### 連携フロー
 
**入社時（Google Workspace にユーザー追加）：**
1. Google Admin でアカウントを作成
2. Webhook または定期バッチ（Google Apps Script）で本システムの REST API を呼び出し
3. 本システムが WordPress ユーザーを新規作成し、初期ロールを `general_staff` で設定
4. 管理者に「新規ユーザーが作成されました。属性情報（部署・承認者等）を設定してください」と通知
**退職時（Google Workspace でアカウントを停止）：**
1. Google Admin でアカウントを停止
2. 定期バッチ（1日1回）で停止済みユーザーを検知
3. 本システムの `employment_status` を `退職` に自動更新し、ログインを無効化（SSO 連携のため Google 側の停止だけで実質ログイン不可になっているが、データの整合性のために本処理も実行する）
#### 実装上の注意
 
- Google Admin SDK の使用には `Admin SDK API` の有効化と、サービスアカウントへのドメイン全体委任が必要。
- 自動作成されたユーザーの「部署・役職・承認者設定」は自動同期の対象外とし、管理者が手動で設定する（Google Workspace の組織ツリーと本システムの部署マスタが必ずしも一致しないため）。

### 6.10. 外部向け申請フォームブリッジ【Tier 3】
 
#### 概要
 
WordPressアカウントを持たない社外スタッフ（パート・業務委託など）向けに、Google Forms で申請を受け付け、Google Apps Script（GAS）経由で本システムの REST API に自動転送する。
 
#### フロー
 
```
社外スタッフ → Google Forms に入力・送信
  → GAS がフォーム回答をトリガーに本システムの REST API を呼び出し
  → wp_approvals に申請レコードを作成
  → 以降は通常の承認フローで処理（Google Chat 通知・カレンダー同期含む）
```
 
#### 対象申請種別
 
外部ブリッジで受け付けるのは以下に限定する（センシティブ情報を扱う申請は対象外）。
 
- 有給休暇申請
- 遅刻・早退申請
- 残業申請
#### 実装上の注意
 
- フォーム回答の送信者認証は Google アカウント（`@gmail.com` 含む）ログインを必須とし、メールアドレスで本システムのユーザーと突合する。
- GAS から本システムへのリクエストには API キー認証（専用キーを `wp_options` に保持）を使用し、外部からの不正リクエストを防ぐ。

## 5. 必要な Google Workspace の設定・前提条件
 
| 設定項目 | 目的 | 関連連携 |
|---|---|---|
| Google Cloud Project の作成 | API 有効化・OAuth 認証情報の取得 | 全連携共通 |
| サービスアカウントの作成 | サーバー間 API 認証（ユーザー同意不要） | 6.2・6.3・6.6・6.8・6.9 |
| ドメイン全体の委任（Domain-Wide Delegation）設定 | 全社員のカレンダー・Gmailへのサービスアカウントアクセス許可 | 6.2・6.8・6.9 |
| OAuth 2.0 クライアント ID の作成（Web アプリ用） | Google SSO のリダイレクト URI 設定 | 6.1 |
| Google Maps API の有効化と API キー発行 | 距離計算 | 6.5 |
| Google Admin SDK の有効化 | ユーザー情報取得 | 6.9 |
 
> **セキュリティ注意事項：** サービスアカウントキー（JSON）および OAuth クライアントシークレットは WordPress の `wp_options` テーブルに暗号化して保存し、Git リポジトリには絶対にコミットしない。
